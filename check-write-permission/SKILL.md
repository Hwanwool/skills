# 写入权限检查

## 核心规则

**规则一（写入前必查）**：每当尝试写入代码或文本时——无论是写入文件，还是准备在对话中输出代码——除非用户**明确要求**在对话中输出代码，否则必须先检查自身是否拥有文件写入权限。

**规则二（无权限即停止）**：若没有文件写入权限，必须立即停止一切写入尝试，不得绕过检查、不得延迟到事后、不得静默继续，直到用户明确指明写入并赋予权限。

## 决策流程

1. **判断写入意图**：本次回复是否包含写入代码或文本的行为？
   - 否 → 正常回答，本 Skill 不适用
   - 是 → 进入步骤 2

2. **判断对话输出豁免**：用户是否**明确要求**在对话中输出代码/文本（而非写入文件）？
   - 是 → 可直接在对话中输出，无需文件写入权限检查
   - 否 → 进入步骤 3

3. **检查文件写入权限**：
   - 当前环境/工具是否具备文件写入能力（沙箱权限、工作区可写性、已授予的写入许可）
   - 是否处于只读模式（如仅查询/解答场景）
   - 用户是否在本次会话中明确授予了写入权限

4. **执行或停止**：
   - 有权限 → 正常执行写入
   - 无权限 → **停止一切写入尝试**

## 无权限时的应对

当检查发现无写入权限时：

1. 立即停止写入行为
2. 明确告知用户：当前没有文件写入权限，因此无法写入 [具体目标文件/内容]
3. 说明所需授权（例如：允许写入工作区文件、允许创建某目录/文件）
4. 等待用户明确指示写入并赋予权限后，再继续执行写入

## 例外情况

- 用户明确要求"在对话中输出代码"——可直接在对话中展示代码，无需文件写入权限检查
- 用户明确授权写入特定文件或目录——在该授权范围内可直接写入
- 用户明确表示"仅需查看/分析，不要改动文件"——不得写入，仅提供分析结果

## 常见误区

- ❌ 无权限时仍尝试写入，失败后静默忽略错误
- ❌ 无权限时把本应写入文件的代码"变通"输出在对话里代替
- ❌ 无权限时自行假设"应该有权限"而不做检查
- ❌ 获得一次授权后无限扩展到其他未授权文件
- ✅ 每次写入前先检查，无权限就停止并说明，获得授权后再写
