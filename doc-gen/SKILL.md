# 功能文档生成（Doc Gen）

## 触发场景

当用户完成一个功能的实现后，要求**生成功能说明文档**（如"整理成文档"、"生成 md 文件"、"把修改内容整理成文档"），启用本 skill。

## 核心原则

1. **基于代码而非记忆** — 所有文档内容必须来自对实际代码、配置文件的阅读，不要凭空虚构或臆测
2. **兼顾设计与使用** — 文档既要让读者理解设计原理，也要能指导实际配置和扩展
3. **结构化优先** — 使用分章节、表格、流程图、代码示例等结构化表达方式
4. **边界完整** — 必须覆盖正常流程和异常/边界行为的处理

## 执行流程

### 步骤 1：理解功能范围

- 从对话历史或用户描述中，明确需要写文档的功能是哪些代码变更
- 整理出功能涉及的核心概念列表（如模式/组件/配置项）
- 确定文档的受众（后续开发者 / 配置策划 / 两者兼顾）

### 步骤 2：阅读工程文件

- 阅读新增或修改的核心代码文件，理解每个方法的职责
- 搜索并阅读相关数据结构定义（如 Excel 导出的 class、ScriptableObject）
- 阅读已有的相关文档（如旧版文档），了解历史背景和需要更新/废弃的内容
- 阅读配置系统的加载流程（如 Excel → JSON → 运行时合并）
- 追踪完整的调用链，理解数据在各层之间的流转

### 步骤 3：设计文档结构

根据功能特点，选择以下章节组合：

| 章节 | 适用场景 | 典型内容 |
|------|---------|---------|
| **概述** | 所有文档 | 功能目的、与旧系统的关系（如有）、核心概念 |
| **各模块/模式详解** | 功能有多种变体 | 每种模式的行为、配置格式、交互方式、边界处理 |
| **配置说明** | 涉及 Excel/JSON 配置 | 每列含义、格式规范、示例 |
| **数据流** | 涉及多阶段处理 | Excel → 运行时加载 → 执行的完整管线 |
| **调用链** | 涉及多模块协作 | 从触发到完成的所有步骤，含条件分支 |
| **配置指南** | 功能需要手动配置 | 分步骤操作指南，含 Excel 示例和 JSON 示例 |
| **关键代码文件** | 所有文档 | 文件路径与作用说明表格 |

### 步骤 4：编写文档内容

- 使用 **markdown** 格式
- 对每种模式/组件，说明：
  - 标识字段及取值
  - 核心行为
  - Excel/配置格式（含每列说明、示例）
  - 交互方式（用户如何操作）
  - 边界/异常行为（耗尽、冲突、空数据等）
- 对数据流，使用文字描述 + 缩进流程图
- 对代码文件，使用表格列出路径和作用
- 所有示例数据应**正确且可运行**

### 步骤 5：自我检查

完成后进行以下检查：

- [ ] 每段内容都有对应的代码/配置文件作为依据？
- [ ] 所有模式/变体的行为都已覆盖？
- [ ] Excel 和 JSON 配置的字段说明完整？
- [ ] 边界情况（如数据为空、链耗尽）有说明？
- [ ] 调用链完整无断点？
- [ ] 关键代码文件路径正确？
- [ ] 文档措辞清晰，新人能读懂？

## 注意事项

- 使用 `Read` 工具阅读代码时优先读取完整方法，不要只读片段，以免遗漏边界处理
- 数据结构定义类（如 Excel 导出的 `partial class`）通常在 `Assets/my/Design/ExportedClasses/` 下
- 如果发现旧版文档中描述的内容已被新代码替代，在"与旧系统的关系"中明确标注废弃
- 文档文件存放在与功能代码同级的目录（如 `Assets/my/Scripts/xxx/`），除非用户指定其他位置
- 如果用户已有同名的文档文件，不要直接覆盖，先阅读旧文件内容再让用户决定是更新还是新建
