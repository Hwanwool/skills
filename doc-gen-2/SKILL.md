# 功能文档生成 · 范文组织结构版（Doc Gen 2）

## 触发场景

用户完成一个功能或工具的实现后，要求**生成说明文档**（如"整理成文档"、"生成 md 文件"、"把这个工具写个说明"），启用本 skill。

与 `doc-gen` 的关系：**内容来源规则继承 `doc-gen`（基于代码而非记忆），组织形式完全换成内置范文的样式**——面向实际操作者，而不是面向开发者。若本 skill 与 `doc-gen` 冲突，以本 skill 为准。

## 范文（格式唯一基准）

以下为格式照准对象。新文档的章节集合、编号方式、标题措辞风格、表格列、步骤写法、图片占位、注意事项编号，都必须能直接与它对照。

```
美术贴图导入Unity工具
1.工具用途：
当前工具用来统一将贴图转换成FBX文件需要的材质，并且把材质关联到FBX文件中
2.开启方法：
[图片]
[图片]
3.命名以及使用规范：
类型          规范                    示例
模型          名字_编号.fbx            Male_01.fbx
贴图          模型名_编号_功能后缀      Male_01_BAC.png
功能后缀：_BAC→基础色、_MRO→金属度、_NOR→法线（可带子后缀如 _NOR_Q）


记：默认目录可在窗口修改，没有其他理由，不要随意更改目录
- Mesh：Assets/Res/Mesh
- Materials：Assets/Res/Materials
- Texture：Assets/Res/Texture

4.生成流程
步骤1.
将命名规范的FBX文件和贴图放到指定目录下：见TexTure目录
[图片]
[图片]
步骤2
  选中FBX文件
[图片]
[图片]
步骤3
  点击批量生成材质（如果有报错，就按照日志提示处理）
[图片]
步骤4
如果没有问题，点击材质关联到FBX，有报错按照日志解决，同上
[图片]
5.注意事项：
贴图匹配相关
1. 匹配是在 Texture 根目录下递归按前缀查找，与 FBX 所在子目录无对应关系，且大小写不敏感（`Character` 与 `character` 都能找到）
2. 严格匹配 `模型名_BAC / _MRO / _NOR` 前缀（`_NOR_Q` 这类子后缀兼容）；同后缀匹配到多张时取字典序第一张并弹警告，建议先清理重名
3. 缺 `_BAC` 的模型直接跳过；缺 `_MRO` / `_NOR` 仍会生成材质（警告），补图后重跑「覆盖更新」即可
贴图导入设置相关
4. 勾选「自动规范化」后，NOR 贴图会被改为 Normal map 类型（不改会导致法线显示错误）；MRO 关 sRGB、BAC 开 sRGB
5. 若某贴图被其它材质共享、不想被动修改导入设置，可临时关闭该选项，由美术手动设置
材质相关
6. 默认 Shader 为 URP/Lit（Metallic 工作流）：_BAC → _BaseMap、_MRO → _MetallicGlossMap、_NOR → _BumpMap，并自动开启 _METALLICSPECGLOSSMAP / _NORMALMAP 关键字
7. URP/Lit 的 `_MetallicGlossMap` 只使用 R 通道（金属度）与 A 通道（光滑度）；MRO 图中的 Roughness(G) / AO(B) 需要自定义 shader（如项目 `Assets/Res/shader/GeneralPBR/PBR_MRO_OBJ.shadergraph`）才能完整生效。这类模型可在窗口 Shader 字段指定该 shader，工具会自动把 MRO 赋到 `_MROMap` 槽
8. FBX 若不在配置的 Mesh 目录内（如从别处拖入），材质会兜底生成到 Materials 根目录，日志有提示
关联 FBX 相关
9. 关联会把该 FBX 的 Material Creation Mode 改为 ImportStandard（Remap 的前提）
10. 若 FBX 没有材质槽（导出时网格未赋予材质），会警告无法关联——需在 DCC（Max/Maya/Blender/DAZ）里给网格赋材质后重新导出
11. FBX 有多个材质槽时按「槽名与模型名匹配」关联；匹配不上会提示手动 Remap
12. 重复点击「关联」会自动跳过已关联项；之前关联过其它材质时会自动替换
13. 关联后场景中已放置的旧实例不会自动更新，需要重新拖入或手动赋材质
其它
14. 三个目录设置通过 EditorPrefs 持久化，重启 Unity 后仍然保留
15. 所有处理结果以窗口下方日志为准，批量处理时请留意警告项
```

范文要点（必须逐条复现）：第 3 节的规范表是三列表格（类型 / 规范 / 示例）；`记：` 起一行做补充约定，其下用 `- ` 列条目；第 4 节的步骤以 `步骤1.` / `步骤2` 起行，每步一到两句，紧跟该步的界面截图；第 5 节先分主题组，全节共用一套连续编号 1..N，不按组重新计数。

## 硬性格式规则

1. **首行是功能名**：纯文本一行，不写 `#`、不加书名号、不加副标题。
2. **章节行**：`N.章节名：`，编号从 1 起、全篇连续、不嵌套层级;章节名后接全角冒号 `：`（范文「4.生成流程」为动作性短语，省略冒号，可照此从简）。
3. **正文是短段落**：一个事实一段，几句话讲完；不用 markdown 标题、不用 `**加粗**`、不用 `---` 分隔线、不用 emoji；除规范表、目录清单、注意事项外，一律不列点。
4. **规范表**：三列 `类型 | 规范 | 示例`，每行必须给真实示例；表的上下各留一个空行。
5. **补充约定**用 `记：` 起行，其下可用 `- ` 列条目（如默认路径清单）。
6. **流程步骤**：`步骤1.` `步骤2` … 逐行起，每步一句话说明做什么，括号内补报错处置（如"如果有报错，就按照日志提示处理"）；同一句里不塞两个动作。
7. **图片占位**：每个界面操作点至少一个 `[图片]` 单独一行，紧跟在描述它的那句话或步骤之后，可连写多个；无法截图时写成 `[图片：<应截取的窗口与操作>]`。
8. **注意事项**：先按主题分组（组名如「贴图匹配相关」「关联 FBX 相关」，裸行、无编号无冒号），组内条目共用全篇一套连续编号 `1. ` `2. `…… 跨组累加，组内不重新计数。
9. **行内表达**：路径、字段名、后缀、shader 名、按钮外的代码标识用反引号；界面按钮用「」（如「覆盖更新」）；数值阈值直接写。
10. **结尾就是注意事项**：不写「总结」「参考」「附」等收尾章节。

## 章节骨架

章节集合与顺序固定如下，无对应内容的章节整章省略、其余编号顺延：

```
[功能名]
1.工具用途：
2.开启方法：
3.命名以及使用规范：
[三列表格]
记：[可选，补充约定与默认路径]
4.生成流程
步骤1.
步骤2
…
5.注意事项：
[主题组]
1. …
```

- **工具用途**：一段话，写这个工具解决什么问题、统一/替代了什么做法；不写背景故事。
- **开启方法**：真实入口——菜单路径（如 `Tools/xxx`）、窗口名、快捷键；配截图。
- **命名以及使用规范**：命名规则、后缀映射、默认目录、单位/格式约定等硬规范；能用表就用表。
- **生成流程**：从准备素材到出结果的完整操作顺序，逐步对应界面动作。
- **注意事项**：所有容易踩的坑、条件限制、降级行为、副作用。

不新增「概述」「数据流」「调用链」「关键代码文件」这类开发者章节。若用户**明确要求**并入设计/配置原理，作为末章 `N.实现说明：` 追加，格式与其他章节一致（短段落 + 表 + 不列点）。

## 内容来源规则（继承 doc-gen）

所有事实必须来自对实际代码、配置文件、界面实现的阅读，不得凭记忆或臆测：

- **工具用途** → 窗口类/工具的注册与主流程入口，看它实际做了什么，不看注释里的自述。
- **开启方法** → 菜单项注册代码（`MenuItem`）/ 快捷键绑定 / 窗口标题字符串，逐字对齐真实路径。
- **命名与规范** → 命名校验、后缀映射表、默认路径常量；正则与后缀表怎么写，表就怎么填。
- **生成流程** → 主流程方法的调用顺序与每个按钮的 `GUILayout.Button` 文本，顺序与按钮名都不许改。
- **注意事项** → 逐条对应代码中的分支与失败路径：搜 `warning` / `LogWarning` / `Debug.LogError` / `throw` / `TryGet` 的 false 分支 / 早退 `return`，每条降级或告警路径落成一条注意事项，写清触发条件与处置方式。

## 执行流程

### 步骤 1：明确范围
从对话历史或用户描述确定：功能/工具名、入口在哪、受众是操作者还是兼顾开发者、是否需要截图占位。

### 步骤 2：阅读工程文件
阅读窗口/工具类与其主流程方法、按钮回调；阅读命名与后缀解析逻辑、默认常量；阅读配置读取与持久化（如 `EditorPrefs`）；追踪主流程从入口到结束的完整调用链。阅读时为每个事实记下出处（文件 + 方法），写文档时逐条回填。

### 步骤 3：把素材归到五章
| 章节 | 素材来源 |
|------|---------|
| 工具用途 | 主流程做什么、替代了什么旧做法 |
| 开启方法 | 菜单注册、窗口类名、快捷键 |
| 命名以及使用规范 | 校验正则、后缀映射、默认路径、格式约定 |
| 生成流程 | 按钮文本 + 按钮回调执行顺序 + 报错处置 |
| 注意事项 | 所有 warning/error/跳过/兜底分支，按主题归组 |

归类时若某素材无章可放，先判断是不是该并入「注意事项」的一条。

### 步骤 4：按骨架撰写
先写五章标题行，再逐章填内容；流程步骤写完立刻补该步的截图占位；注意事项先列主题组再统一编号，最后检查编号连续。

### 步骤 5：自检
- [ ] 首行是功能名，全篇无 markdown 标题、无 `**加粗**`、无 `---`、无 emoji？
- [ ] 章节编号从 1 连续，章节名后带全角冒号，顺序与骨架一致？
- [ ] 规范表三列齐全，每行都有真实示例？
- [ ] 每个界面操作点都有 `[图片]` 占位？
- [ ] 流程步骤顺序与按钮文本和代码一致，报错处置已写明指向日志？
- [ ] 注意事项已按主题分组，且全节编号连续不重开？
- [ ] 每条注意事项都能指到代码中的告警/分支/兜底逻辑？
- [ ] 正文全是短段落，没有把说明写成清单？
- [ ] 文档已写入 `C:\Users\11\Desktop\流程归档\`（或用户指定位置），文件名不与其他文档混淆？
- [ ] 新人照文档能独立跑通一遍？

## 注意事项（本 skill 自身）

- 文档文件默认写入 `C:\Users\11\Desktop\流程归档\`，文件名用功能名（如 `Excel动画配置与SO生成指南.md`）；用户明确指定其他位置时以用户指定为准。
- 若目标路径已有同名文档，先读旧文件再让用户决定更新还是新建，不要直接覆盖。
- 范文中的 Unity/美术贴图业务词汇仅是样式载体，不要照搬其内容或领域词。
- 用户提供范文片段时，以用户提供的为新基准；否则一律以本 skill 内置范文为准。
